# 新規団体向け 初期化チェックリスト

`database.xlsx` と `lib/orbit/seed.ts` にはサンプル／デモ用のデータが入っています。
自団体で使い始める前に、以下の順番で「まっさらな状態」に置き換えてください。

## 1. スプレッドシートの準備

- [ ] `database.xlsx` の内容を Google スプレッドシートにインポートする（または
      同じシート名・列名で新規に作成する。詳細は `gas/README.md` の
      「1. シートの列構成」を参照）
- [ ] Members / Projects / Tasks の各シートで、**黄色い背景の行（入力例）をすべて
      削除する**
- [ ] `使い方` シートはそのまま残しても、削除しても構いません（動作には影響しません）

> `lib/orbit/seed.ts` はスプレッドシート未設定時（`.env.local` が空欄）に使われる
> ローカルモックデータで、スプレッドシートには一切影響しません。動作確認用として
> そのまま残しておいて問題ありません。

## 2. 最初の管理者（代表）を登録する

現バージョンのログインは、Membersシートに登録されているメンバーの中から選んで
「なりすます」形の簡易画面です（本人確認なし）。そのため、**最低1人、`role` 列が
`代表`（または後述の最上位ロール）のメンバー行を、他のメンバーより先に手入力で
Membersシートへ追加しておく**必要があります。そうしないと、誰も管理者画面に
入れない状態になってしまいます。

- [ ] Membersシートに1行目（サンプル削除後の最初の実データ行）として、団体の
      代表者を `id` / `name` / `role`(`代表`) / `email` を最低限入力して追加する
- [ ] Apps Script をデプロイ済みなら、Orbit にログインしてこの代表者としてログインし、
      Admin → Members から残りのメンバーを順次登録していく（`role` を指定すれば
      その場で管理者として登録することも可能）

## 3. 役職レベルを自団体に合わせる

初期値は `班長` → `事業責任者` → `代表` の3段階です。自団体の組織構造に合わせて
Admin → Tags から自由に追加・削除・改名できます。

- [ ] 自団体の役職名に合わせてロールレベルを調整する（例: `幹部` のみの2段階に
      減らす、`副代表` を追加するなど）
- [ ] 最下位以外のロール（初期値では `事業責任者`・`代表`）は自動的にフル管理者権限を
      持ちます。最下位ロール（初期値では `班長`）は「担当プロジェクト」で
      割り当てた範囲だけが見える、プロジェクト限定の管理者になります
- [ ] 権限レベルごとの管理画面の表示範囲（Admin → Tags の「権限レベルごとの表示範囲」）
      を必要に応じて調整する

## 4. プロジェクト・タグ類を用意する

- [ ] Projectsシートに自団体の実際のプロジェクト（部・チーム・企画など）を登録する
- [ ] Admin → Tags で「要求スキル」「カテゴリ」の選択肢を自団体の実態に合わせて
      整理する（初期値はFSIF向けの汎用的な例です）
- [ ] 必要であればプロジェクトの種類ごとのテンプレートタスク（Admin → Projects）を
      設定する

## 5. 通知・連携の設定（任意）

- [ ] メンバーの `email` を入力し、`notify_new_task` を必要な人だけ `TRUE` にする
      （新規タスク登録・確認待ちの通知に使われます）
- [ ] プロフィール画像アップロードを使う場合は `gas/README.md` の「4.5」を参照し
      Google Drive フォルダを用意する
- [ ] 選択肢プール（要求スキル・カテゴリ・権限レベルなど）を全員の画面で共有したい
      場合は `gas/README.md` の「4.6」を参照し Settings シートを追加する
- [ ] Discord 通知を使う場合は `gas/README.md` の「Discord Webhook 連携」を参照し
      Webhook URL を設定する

## 6. デプロイ前の最終確認

- [ ] GitHub Secrets（`MEMBERS_CSV` / `PROJECTS_CSV` / `TASKS_CSV` / `CSV_GAS`、
      任意で `DRIVE_FOLDER_ID` / `SETTINGS_CSV`）が自団体のURLに設定されている
- [ ] `next.config.mjs` の `repoName` 定数が実際のリポジトリ名と一致している
- [ ] `pnpm build` がローカルで成功する
- [ ] デプロイ後、実際に代表アカウントでログインし、タスクの登録→承認→完了の
      一連の流れが動作することを確認する

これで自団体専用のOrbitインスタンスとして使い始められます。ルートの
[`README.md`](../README.md) と [`gas/README.md`](../gas/README.md) も合わせて
参照してください。
