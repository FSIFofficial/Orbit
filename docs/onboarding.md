# Orbit 新規団体向け セットアップガイド

このガイドは、**GitHub・GAS（Google Apps Script）を使ったことがない方**でも
Orbit を自分の団体で使い始められるよう、手順を一つひとつ解説しています。

所要時間の目安: **1〜2時間**（初めての場合）

---

## はじめに

Orbit は Google スプレッドシートをデータベースとして使い、
GitHub Pages で公開する静的Webアプリです。

```
あなたの団体が使う Orbit のしくみ:

  Google スプレッドシート ←→ Apps Script（書き込み）
           ↑
    CSV で読み込み
           ↑
  GitHub Actions（ビルド）
           ↑
  GitHub Pages（公開サイト）
```

すべて無料で使えるサービスで成り立っています。

---

## ステップ 0: 必要なものを確認する

- **Google アカウント**（スプレッドシート・GAS に使用）
- **GitHub アカウント**（リポジトリの管理・公開に使用）

まだお持ちでない場合は作成してください。

---

## ステップ 1: リポジトリをコピーする（Fork）

> **用語: Fork（フォーク）とは?**  
> GitHub 上の公開リポジトリ（プログラムの倉庫）を、自分のアカウントにコピーする操作です。

1. [Orbit のリポジトリページ](https://github.com/fsifofficial/orbit) を開く
2. 右上の **「Fork」** ボタンをクリック
3. 「Owner」に自分のアカウント（または団体の Organization）が表示されていることを確認
4. 「Repository name」は変えなくてもよい（変える場合は後の設定にも反映してください）
5. **「Create fork」** をクリック

これで自分のアカウントに Orbit のコピーができました。

---

## ステップ 2: スプレッドシートを用意する

### 2-1. サンプルファイルをインポートする

1. リポジトリの `database.xlsx` をダウンロードする  
   （ファイル名をクリック → 「Raw」→ ファイルを保存、または右クリックで「名前を付けて保存」）
2. [Google ドライブ](https://drive.google.com) を開く
3. 「マイドライブ」に先ほどの `database.xlsx` をドラッグ&ドロップ
4. アップロードされたファイルをダブルクリック → 「Google スプレッドシートで開く」を選択

これで `Members`・`Projects`・`Tasks` の 3 シートが入ったスプレッドシートが開きます。

### 2-2. サンプルデータを削除する

各シートの **黄色い背景の行（サンプルデータ）をすべて削除**してください。  
（1行目のヘッダー行は残してください）

> `使い方` シートはそのまま残しても、削除しても構いません。

### 2-3. 最初の管理者（代表）を登録する

スプレッドシートで管理者を登録しておかないと、誰もAdmin画面に入れません。

1. `Members` シートに移動する
2. 2行目（ヘッダーの次の行）に以下を入力する:

| 列名 | 入力例 |
|---|---|
| id | `m-001` |
| name | `山田 太郎` |
| role | `代表` |
| email | `yamada@example.com` |

他の列は空欄でも動きます。後からAdmin画面で追加できます。

---

## ステップ 3: Apps Script（GAS）を設定する

> **用語: Apps Script（GAS）とは?**  
> Google スプレッドシートに「プログラム」を書いて実行する機能です。  
> Orbit はここに `Code.gs` を貼り付けることで、データの書き込み口を作ります。

### 3-1. Apps Script を開く

1. スプレッドシートの上部メニュー **「拡張機能」→「Apps Script」** をクリック
2. 新しいタブでエディタが開く

### 3-2. Code.gs の中身を貼り替える

1. 左側の `コード.gs` をクリックして開く
2. 中身をすべて選択（`Ctrl+A` または `Cmd+A`）して削除
3. リポジトリの `gas/Code.gs` の内容をすべてコピー&ペースト
4. **「保存」**（フロッピーアイコン、または `Ctrl+S`）

### 3-3. Web App としてデプロイする

1. 右上の **「デプロイ」→「新しいデプロイ」** をクリック
2. 「種類の選択」で **「ウェブアプリ」** を選ぶ
3. 設定する:
   - **説明**: 任意（例: `Orbit v1`）
   - **実行するユーザー**: `自分`
   - **アクセスできるユーザー**: `全員`
4. **「デプロイ」** をクリック
5. 「Googleアカウントへのアクセスをリクエストしています」という画面が出たら:
   - 「高度な設定」→「（プロジェクト名）に移動（安全ではないページ）」→「許可」
6. 表示された **「ウェブアプリ URL」（`/exec` で終わるURL）** をコピーしてメモしておく

---

## ステップ 4: Google OAuth クライアントIDを取得する

Orbit のログインは Google アカウントを使います。そのため Google Cloud Console でクライアントIDを取得する必要があります。

> 少し手順が多いですが、**一度だけ**の設定です。

### 4-1. Google Cloud Console でプロジェクトを作成する

1. [Google Cloud Console](https://console.cloud.google.com/) を開く（Google アカウントでログイン）
2. 上部の「プロジェクトを選択」→ **「新しいプロジェクト」** をクリック
3. プロジェクト名を入力（例: `Orbit`）→「作成」

### 4-2. OAuth 同意画面を設定する

1. 左メニュー **「APIとサービス」→「OAuth 同意画面」**
2. ユーザーの種類: **「外部」** → 「作成」
3. 「アプリ名」に `Orbit`、「ユーザーサポートメール」と「デベロッパーの連絡先情報」にメールアドレスを入力
4. 「保存して次へ」を何度かクリックして完了

### 4-3. OAuthクライアントIDを作成する

1. 左メニュー **「APIとサービス」→「認証情報」**
2. 上部 **「認証情報を作成」→「OAuthクライアントID」**
3. アプリケーションの種類: **「ウェブアプリケーション」**
4. 名前を入力（例: `Orbit Web`）
5. 「承認済みのJavaScriptオリジン」に以下を追加:
   - `https://<GitHubユーザー名または組織名>.github.io`  
     （例: `https://myteam.github.io`）
   - `http://localhost:3000`（開発用、必要であれば）
6. 「作成」→ 表示された **「クライアントID」** をコピーしてメモしておく  
   （`123456789-xxxx.apps.googleusercontent.com` という形式）

### 4-4. Apps Script にも登録する

1. Apps Script エディタに戻る
2. 左メニュー **「プロジェクトの設定」（歯車アイコン）**
3. 「スクリプト プロパティ」→「プロパティを追加」
4. プロパティ名: `GOOGLE_OAUTH_CLIENT_ID`、値: コピーしたクライアントID
5. 「スクリプトプロパティを保存」

---

## ステップ 5: シートを「ウェブに公開」する

各シートの CSV URL を取得します。Members・Projects・Tasks の3枚について同じ操作をします。

1. スプレッドシートの上部メニュー **「ファイル」→「共有」→「ウェブに公開」**
2. ドロップダウンで **「Members」** を選択（最初は「ドキュメント全体」になっている）
3. 右のドロップダウンを **「カンマ区切りの値（.csv）」** に変更
4. **「発行」** をクリック
5. 表示されたURLをコピーしてメモ → `MEMBERS_CSV` 用
6. 同じ操作を **Projects**・**Tasks** でも繰り返す

---

## ステップ 6: GitHub Secrets を設定する

GitHubリポジトリに URL などを登録します。

1. Fork したリポジトリのページを開く
2. **「Settings」**（右端のタブ）→ 左メニュー **「Secrets and variables」→「Actions」**
3. **「New repository secret」** をクリックして以下を1つずつ追加:

| Name（Secret名） | Value（値） |
|---|---|
| `MEMBERS_CSV` | 手順5でコピーした Members のURL |
| `PROJECTS_CSV` | 手順5でコピーした Projects のURL |
| `TASKS_CSV` | 手順5でコピーした Tasks のURL |
| `CSV_GAS` | 手順3-3でコピーした `/exec` で終わるURL |
| `NEXT_PUBLIC_GOOGLE_OAUTH_CLIENT_ID` | 手順4-3でコピーしたクライアントID |

4. 追加後、5つの Secrets が揃っていることを確認する

---

## ステップ 7: リポジトリ名を設定する

`next.config.mjs` を編集してリポジトリ名を合わせます。

> **用語: リポジトリ名とは?**  
> GitHub の URL に含まれる名前です。`https://github.com/myteam/orbit-myteam` であれば `orbit-myteam` です。

1. リポジトリの `next.config.mjs` をクリックして開く
2. 右上の鉛筆アイコン（「Edit this file」）をクリック
3. `const repoName = 'orbit'` という行を探して、`orbit` の部分を実際のリポジトリ名に変更する  
   例: `const repoName = 'orbit-myteam'`
4. 「Commit changes」→「Commit changes」で保存

---

## ステップ 8: デプロイする

GitHub Actions が自動的にビルド・デプロイします。

1. リポジトリの **「Actions」** タブを開く
2. 一覧にワークフロー（`Deploy to GitHub Pages` など）が表示されていれば自動実行されている
   - まだ実行されていない場合は、**「Deploy to GitHub Pages」→「Run workflow」** をクリック
3. ✅ のマークが付いたら成功
4. **「Settings」→「Pages」** を開いて公開URLを確認する  
   例: `https://myteam.github.io/orbit-myteam/`

---

## ステップ 9: 動作確認

1. 公開URLにアクセスする
2. **「Googleでサインイン」** で代表アカウントのGoogleアカウントでログインする
3. ログイン後に「Admin」タブが表示されれば成功
4. **Admin → Membersから残りのメンバーを登録する**
   - 役職を「一般」以外にするとその場で管理者として登録できます

---

## ステップ 10: 初期設定を行う

### 役職レベルの調整

初期値は `班長` → `事業責任者` → `代表` の3段階です。
**Admin → Tags** から自由に追加・削除・改名できます。

- 自団体の役職名に合わせて調整してください（例: `幹部` のみの2段階など）
- 最下位以外のロールは自動的に組織全体のAdmin画面にフルアクセスできます
- 最下位ロールは「担当プロジェクト」で割り当てた範囲に限定されます

### スキル・カテゴリの調整

**Admin → Tags** から「要求スキル」「カテゴリ」の選択肢を自団体の実態に合わせて整理してください（初期値はFSIF向けの汎用的な例です）。

### Settings シートの設定（任意・推奨）

選択肢プールや設定を **全員の画面で共有する**には Settings シートを追加します（`gas/README.md` の「4.6」参照）。
複数人が Admin 設定を行う場合は設定することを推奨します。

### 通知メールの設定（任意）

メンバーの `email` 列を入力し、通知を受け取りたい人だけ `notify_new_task` を `TRUE` にしてください。

## よくある質問

### Q: デプロイしたけど古い画面が表示される

GitHub Actions が完了してから数分かかる場合があります。ブラウザのキャッシュをクリア（`Ctrl+Shift+R` または `Cmd+Shift+R`）してみてください。

### Q: ログインできない / 「メンバーが見つかりません」と表示される

- Members シートにそのGoogleアカウントのメールアドレス（`email` 列）が登録されているか確認してください
- Secrets の `MEMBERS_CSV` のURLが正しいか確認してください
- スプレッドシートが「ウェブに公開」されているか確認してください

### Q: データを更新したのに画面に反映されない

Google スプレッドシートの「ウェブに公開」CSVは、Googleのキャッシュで反映に数分かかります。しばらく待ってからリロードしてください。

### Q: メール通知が届かない

`gas/README.md` の「8. メール通知が届かないときの確認手順」を参照してください。

### Q: Apps Script の更新方法がわからない

Orbit のバージョンアップ時などに `Code.gs` を更新する場合:
1. Apps Script エディタで `Code.gs` の中身を新しいものに貼り替えて保存
2. 「デプロイ」→「デプロイを管理」→ 対象のウェブアプリの鉛筆アイコン
3. バージョン: **「新規」** を選んで「デプロイ」

### Q: Settings シートって必要?

必須ではありませんが、設定することを推奨します。  
設定しない場合、スキル選択肢・カテゴリ・権限レベルなどは**自分のブラウザにのみ保存**され、他のメンバーには反映されません。

### Q: 「改善を要望する」ボタンはどこ?

右上のユーザーメニュー（名前の横のアイコン）をクリックすると「改善を要望する」ボタンがあります。

### プロフィール画像

`gas/README.md` の「4.5. プロフィール画像アップロード」を参照してください。

### Discord 通知

`gas/README.md` の「4.7. Discord Webhook 連携」を参照してください。

### 定期タスクの自動生成

`gas/README.md` の「6. 定期タスクの自動生成（サーバー側トリガー）」を参照してください。

### スキルレベルアップ閾値

Admin → Tags の「Settings（スキル設定）」から設定できます。  
どれだけタスクをこなしたらスキルレベルが上がるかを細かく設定できます。

### 検定（クイズ）

Admin → 検定 からスキル確認テストを作成できます。合格するとスキルレベルが上がります。

### レーダーチャート

個人ページに表示されるスキルのレーダーチャートの軸を Admin → レーダー でカスタマイズできます。

### 経費申請

Admin → 経費申請 からカテゴリと承認フローを設定すると、メンバーが個人ページから経費申請を提出できます。

### カスタムフォーム

Admin → フォーム から団体独自の申請フォームを作成できます（研修参加申請・備品申請など）。

### 人材データベース

Admin → 人材DB でメンバー全員のスキル・キャリア情報を Excel 風の表で一覧・編集できます。CSVでのエクスポート・インポートにも対応しています。
